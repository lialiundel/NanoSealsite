# NanoSeal — сайт с защитной наклейкой и QR

**Готовая папка для GitHub Pages.** Загружайте **содержимое этой папки** в корень репозитория, а не ZIP-файл и не вложенную папку.

## Публикация
1. Откройте репозиторий GitHub → Add file → Upload files.
2. Перетащите `index.html`, `admin.html`, `README.md`, `.nojekyll` и **папку `assets` целиком**.
3. Commit changes.
4. Settings → Pages → Deploy from a branch → `main` → `/(root)` → Save.
5. Через несколько минут откройте `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

## Как демонстрировать
1. Откройте «Для производителя», введите название товара и партию.
2. Нажмите «Создать наклейку с QR». Появится макет с голографическим рисунком, серийным номером и **QR внутри наклейки**.
3. Нажмите «Скачать наклейку SVG» и откройте файл. QR ведёт на страницу проверки NanoSeal.
4. Отсканируйте QR **обычной камерой телефона**. На открывшемся сайте подпись проверится автоматически.
5. Дополнительно осмотрите физическую наклейку: перелив, рельеф, следы отклеивания.

## Важные ограничения
- Цветной градиент на макете — **не настоящая голограмма**. Для физического нанорельефа нужен специализированный изготовитель.
- В GitHub Pages нет общего сервера. Записи и статус отзыва хранятся **только в браузере производителя**; на другом устройстве цифровая подпись проверяется, но локальный отзыв не виден.
- Подпись не доказывает подлинность товара: QR может быть скопирован. Нет подтверждения личности владельца ключа.
- «Сканировать камерой» запрашивает доступ к камере через HTTPS. Если встроенный BarcodeDetector недоступен, используется библиотека jsQR, загружаемая с CDN. Для первого запуска сканера нужен интернет и доступ к CDN. Если доступ запрещён, разрешите камеру для github.io в настройках браузера. Есть резервная загрузка фото и штатная камера телефона.
- Не используйте проект как промышленную систему аутентификации или вместо обязательной маркировки.


## Организация и оптическая решётка
В панели производителя появился профиль организации по почте **или** телефону. Данные сохраняются в localStorage текущего браузера. **Это не настоящая регистрация с подтверждением email/SMS и не авторизация**: для этого нужен внешний backend (например, Supabase Auth или Firebase Authentication). Никогда не используйте этот MVP для подтверждения личности производителя.

При выпуске наклейки система случайно выбирает одну из физически согласованных комбинаций плотности штрихов и длины волны блеска (600/1200 штр./мм, 400/500 нм). Шаг вычисляется как d = 10^6 / N нм; угол первого порядка при нормальном падении для 550 нм — arcsin(550/d). Параметры сохраняются внутри подписанного QR и выводятся в техническом задании TXT. Источники эталонных **жёстких отражательных** решёток: https://www.edmundoptics.com/p/600-grooves-125-x-25mm-400nm-ruled-diffraction-grating/4656/ и https://www.edmundoptics.de/p/1200-grooves-125-x-25mm-400nm-ruled-diffraction-grating/4664/ и https://www.edmundoptics.de/p/1200-grooves-125-x-25mm-500nm-ruled-diffraction-grating/4727/ . Это не каталог сертифицированных гибких голографических пломб. Для изготовления требуется отдельное согласование глубины рельефа, тиражирования, подложки и разрушаемого клея.


## НАСТОЯЩАЯ РЕГИСТРАЦИЯ ПО EMAIL (Supabase Auth)

GitHub Pages — статический хостинг, поэтому для подтверждения email нужен внешний сервис.

1. Создайте бесплатный проект на https://supabase.com/dashboard .
2. Откройте **Project Settings → API** (или **Connect → API Keys**). Скопируйте **Project URL** и **publishable key** (`sb_publishable_...`) или старый **anon public** key. **Никогда не копируйте `service_role` / secret key**.
3. Откройте файл `assets/auth-config.js` и значения уже заполнены для вашего проекта. Опубликуйте файл на GitHub. Эти два публичных значения допустимы в открытом репозитории.
4. В Supabase: **Authentication → Providers → Email**: включите Email provider и **Confirm email**.
5. В **Authentication → URL Configuration** установите **Site URL** `https://lialiundel.github.io/sealnano/` (или актуальный адрес вашего репозитория) и добавьте **Redirect URL** `https://lialiundel.github.io/sealnano/admin.html`. Укажите точное имя репозитория с учётом регистра.
6. Откройте `admin.html` на опубликованном сайте. Введите email и пароль (8+ символов), нажмите «Зарегистрироваться». Перейдите по ссылке в письме, затем войдите.
7. Заполните профиль организации и выпускайте наклейки. Для входа с другого устройства используйте тот же email и пароль.

**Что реально реализовано:** регистрация/вход/выход через Supabase Auth, подтверждение email, сессия с автоматическим обновлением, блокировка выпуска наклеек до входа и заполнения профиля. **Что НЕ реализовано:** SMS-регистрация, проверка юридического лица, серверный реестр наклеек, перенос приватных ключей/товаров между устройствами, защита от создания нескольких аккаунтов, управление ролями организации. Профиль организации и выпущенные товары по-прежнему сохраняются только локально. Это демонстрационный прототип, не система промышленной аутентификации.

Если письма не приходят: проверьте папку «Спам», настройки почтового провайдера Supabase и ограничения встроенного SMTP. Для публичного проекта нужен собственный SMTP.

## Настройка для подключенного проекта
В `assets/auth-config.js` уже указаны Project URL и публичный publishable key. **Никогда не добавляйте secret/service_role ключи в репозиторий.**

В Supabase → Authentication → URL Configuration задайте Site URL `https://lialiundel.github.io/sealnano/` и Redirect URL `https://lialiundel.github.io/sealnano/admin.html`. Если сайт размещён в другом репозитории, замените адреса на действующие. В Authentication → Providers → Email включите email-провайдер и подтверждение адреса.
